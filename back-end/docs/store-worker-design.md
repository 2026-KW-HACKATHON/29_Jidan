# 근무자 관리 API 설계

Figma 근무자 목록(269:830), 정기 상세(192:5251), 대타 상세(270:2108) 기준의 구현 전 계약이다. 고용 계약/급여/근무 배정 관리와 실제 서버·DB 처리는 포함하지 않는다.

## 목록과 상세

- `GET /api/stores/{storeId}/workers?view=ACTIVE`: 현재 자료 접근이 있는 근무자를 페이지 조회한다. ENDED는 종료 이력, ALL은 전체다.
- `GET /api/stores/{storeId}/workers/{workerId}`: 해당 매장의 근무자 접근 이력을 상세 조회한다. 접근 이력이 없는 근무자는 404 STORE_WORKER_NOT_FOUND다.

가입 완료 ACTIVE OWNER의 회원 세션과 현재 매장 소유권·APPROVED를 매 요청 확인한다. 없는/타 점주 매장은 404, 본인 승인 대기는 403이다. 전체 회원 프로필·Google 이메일·연락처·생일·가입 경력은 노출하지 않고 이름·업무·접근 유형/기간·자료 권한만 반환한다. 초대 화면의 업무 입력이 없어 REGULAR의 dutyLabel은 null을 허용한다. 수정 경로는 후속 설계 대상이며 값이 없으면 ‘담당 업무 미등록’으로 표시할 수 있다.

REGULAR는 초대 수락에서 시작하고, 사용자가 정한 선택 접근 기한이 있거나 별도 종료 전까지다. TEMPORARY는 후속 대타 확정에서 즉시 생성하며 근무 종료 시각에 접근이 끝난다. 대타 모집/확정 API는 이번 범위에 추가하지 않는다. 응답은 자료 접근 상태이며 실제 고용 상태와 동일하다고 간주하지 않는다.

각 권한은 startedAt<=now이고 validUntil이 null 또는 now<validUntil이며 revokedAt이 없을 때 유효하다. 만료는 EXPIRED, 수동 종료는 REVOKED다. 유효 권한의 종료까지 24시간 이내는 EXPIRING이라는 제안이다. 근무자 전체는 하나라도 ACTIVE인 권한이 있으면 ACTIVE, 유효 권한이 모두 EXPIRING이면 EXPIRING, 유효 권한이 없으면 ENDED다. 무기한 정기와 만료 예정 대타를 함께 가진 근무자는 ACTIVE다. 실제 자료 API에서는 근무자 계정 ACTIVE와 매장 승인도 재검증한다.

여러 접근이 있어도 workerId마다 목록 한 항목이며 accessGrants로 개별 이력을 묶는다. 접근 이력은 시작 시각/ID 내림차순, 근무자는 최근 접근 시작 시각/회원 ID 내림차순이다. activeCount는 서로 다른 유효 근무자 수이며 expiringCount를 포함한다. 목록과 필터 무관 건수·asOf는 한 읽기 스냅샷 기준이다. 기본 페이지 1/20·최대 100·정렬·24시간 임박 조건은 설계 제안이다.

Schema 검사는 접근 유형·기간·수동 종료/만료·세 자료 권한 일치, 여러 접근의 근무자 상태 구조, 빈 목록/페이지를 확인한다. 실제 기간 계산·중복 없는 근무자 집계·인증/인가·개인정보 투영은 서버 통합 검증 대상이다.
