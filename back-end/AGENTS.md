# 백엔드 작업 규칙

이 문서는 `back-end/` 전체에 적용하며, 저장소 루트의 [AGENTS.md](../AGENTS.md)와 협업 문서를 함께 따른다.

## E2E 테스트 필수 작성

- API 또는 백엔드 동작을 추가·수정하면 해당 사용자 시나리오의 E2E 테스트를 반드시 작성하거나 갱신한다. 버그 수정은 같은 문제가 재발하면 실패하는 회귀 시나리오를 포함한다.
- 실제 서버에 HTTP 요청을 보내고 실제 테스트 DB를 사용한다. 서버의 handler나 DB 의존성을 mock으로 교체한 테스트만으로 E2E 검증을 완료했다고 판단하지 않는다.
- 응답 상태·본문뿐 아니라, 별도 DB 연결로 commit 결과를 확인하고 API 재조회로 저장 결과를 검증한다. 거부·실패한 요청은 기존 데이터 보존과 부분 저장 여부도 확인한다.
- 테스트는 격리된 테스트 DB에서 실행한다. 개발·운영 DB에 테스트 데이터를 생성하거나 초기화하지 않는다. 실행 방법은 [API·DB 테스트 안내](testing/README.md)를 따른다.
- CI 컨테이너의 API·DB E2E, 배포 서버 검증, 브라우저·외부 서비스 연동 검증을 구분한다. fixture로 대신한 경계와 미검증 범위를 기록하고, 실제 실행한 범위만 검증 완료로 보고한다.

## 엣지케이스 포함

정상 흐름과 함께 변경에 관련된 엣지케이스를 반드시 포함한다. 아래 항목을 검토하고 해당하는 시나리오를 테스트한다.

- 입력: 누락·null·빈 값, 잘못된 형식, 최소·최대 경계와 경계 초과, 중복 값, 날짜·시간·주 경계.
- 인증·권한: 미인증, 만료·폐기된 세션, 잘못된 역할, 다른 사용자의 자원 접근, CSRF·Origin 거부.
- 상태·재시도: 존재하지 않거나 삭제된 자원, 허용되지 않는 상태 전이, 중복 요청, 멱등 재시도와 key 충돌.
- 저장·동시성: 부분 저장·롤백, 연관 행 교체·삭제, 동시 요청의 갱신 유실·중복 생성·경합.
- 외부 연동: 실패·타임아웃·잘못된 응답과 그때의 데이터·세션 보존. 실제 외부 연동을 검증하지 않았다면 그 한계를 명시한다.

## 작성 후 누락 재점검

- 테스트를 작성하거나 수정한 뒤에는 **항상 놓친 시나리오가 있는지 다시 점검한다.** 테스트 통과만으로 작업을 끝내지 않는다.
- 요구사항·API 계약·실제 구현의 분기와 상태 전이를 테스트 목록에 대조하고, 정상·거부·실패·재시도·동시성 경로 및 위 엣지케이스의 누락을 확인한다.
- 응답만 검사해 실제 저장 누락을 놓치거나, fixture·mock이 검증할 동작을 우회하거나, 테스트가 skip되어 검증이 빠진 부분이 없는지 확인한다.
- 누락이 발견되면 테스트를 보완하고 영향을 받는 테스트를 다시 실행한 뒤 재점검한다. 해결되지 않은 실패·skip·미검증 범위와 이유는 작업 결과 및 PR에 명시한다.
- 검증과 누락 재점검을 마친 테스트는 해당 구현과 같은 원자 커밋에 포함한다.
