## 화면 확인

`/__preview`의 점주 공고 등록·관리·지원자 확인 메뉴에서 모든 예시를 선택합니다.

- `/__owner/jobs?view=create`: 실제 입력을 시작하는 빈 등록 화면
- `/__owner/jobs?view=create&step=2`, `step=3`: 입력을 갖춘 단계별 샘플
- `picker=part`, `experience`, `payment`: 각 단계의 선택창
- `result=success`, `result=failure&fail=1`: 등록 결과 예시
- `/__owner/jobs`: 모집 중 공고 목록. `tab=closed`는 마감 목록, `empty=1`은 빈 목록
- `view=detail&id=open&overlay=close`, `overlay=closed`: 마감 확인·완료
- `view=applicants&id=open`: 지원자 목록. `noApplicants=1`은 지원자 없음
- `view=applicants&id=open&review=park`: 박지원 지원서
- `view=applicants&id=open&review=kim&readonly=1`: 김래원 열람 전용 지원서
- `view=applicants&id=open&overlay=request&applicant=park`: 근무 요청 확인
- `overlay=request-complete`: 근무 요청 완료, `requestFail=1`: 첫 요청 실패·재시도

미리보기 안에서는 등록·마감 결과를 다음 화면에 전달합니다. 새로고침하거나 다른 샘플 예시로 전환하면 샘플 데이터로 초기화합니다. 점주 홈과 매장 관리 메뉴에서도 진입할 수 있습니다. 홈의 공고 카드는 해당 공고의 지원자 목록으로 연결합니다. 홈에서 등록을 시작하면 첫 단계의 뒤로가기는 홈으로, 직접 등록 화면에 진입하면 공고 관리로 돌아갑니다.

## 연동 경계

등록은 `OwnerJobService.create(draft, signal)`, 마감은 `CloseJobService.close(jobId, signal)`을 주입합니다. 기본 등록 서비스는 미연동 오류를 반환하며 HTTP 경로를 정의하지 않습니다. 미리보기는 메모리의 샘플 서비스만 사용합니다. 실제 계정·공고·지원서 데이터를 조회하거나 변경하지 않습니다.

지원서의 근무 요청 버튼은 `onRequest(applicant)`를 전달합니다. `WorkRequestService.request(jobId, applicantId, signal)`을 주입해 확인·요청·완료·실패 후 재시도를 처리합니다. 서비스 미설정 시 성공으로 간주하지 않습니다. 미리보기에서만 샘플 요청을 처리하며 실제 전송과 알림 예약은 수행하지 않습니다. 완료 화면의 1시간 안내는 Figma 예시 문구이며 실제 타이머나 알림 동작이 아닙니다. 요청 완료가 공고 마감·선정 완료를 의미하지 않습니다. 열람 전용·마감 상태에는 요청 버튼을 표시하지 않습니다.

## 입력 및 비동기 처리

필수 입력·실존 날짜·양수 시급·30분 단위 시간을 검증합니다. 종료 시각과 다음 날 여부를 분리해 자정을 넘는 근무를 처리하고, 0시간 이하 또는 24시간 초과 근무는 거부합니다. 텍스트 예시는 placeholder이며 실제 입력값이 아닙니다. 근무 파트와 지급 시점은 Figma의 기본 선택값을 사용합니다.

화면 입력 제한은 업무명 100자, 설명·선택 안내 2,000자, 시급 9자리입니다. 이는 화면 보호용 제한이며 서버의 확정된 정책이나 API 명세가 아닙니다. 연동 시 명세와 함께 조정합니다.

단계 이동·실패 후 입력을 유지합니다. `useCommand`로 중복 실행·10초 제한·취소 및 화면 이탈 후 응답을 처리합니다. 서비스는 AbortSignal을 준수해야 하며 실제 서버 작업 취소와 응답 유실 시 중복 방지는 서버 연동 때 확인해야 합니다.
