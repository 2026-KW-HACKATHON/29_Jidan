미리보기는 DEV 전용이며 실제 계정·매장을 생성하지 않습니다. `preview.v2.` 저장소를 사용하고 인증 쿠키를 만들지 않습니다. 기본 진입은 성명·연락처·매장 정보를 빈 값으로 시작하고 사용자가 입력한 내용만 새로고침 시 복원합니다. 기존 자동 입력 샘플은 복원하지 않습니다. 명시적인 단계 쿼리는 화면 비교용이며 store 단계의 매장 정보도 비어 있습니다. review/pending 단계만 완성된 샘플을 제공합니다. 미리보기의 접수 결과는 샘플입니다.

실제 경로 `/signup/owner`는 기존 AuthFlow 가드를 사용합니다. 실제 서버 정보가 없으면 실패 안내를 표시합니다. `/home`의 OWNER도 서비스의 접수 상태 조회를 사용하며, 승인된 점주 홈은 별도 구현 대상입니다.

## 동작

- 기본 정보 → 매장 정보 → 확인 → 승인 대기. 이전 단계와 확인 화면의 수정을 지원하며 입력을 유지합니다.
- 연락처·매장 전화번호·사업자 번호는 숫자만 허용하고 자릿수를 제한하며 하이픈을 자동 삽입합니다. 붙여넣기·전각 숫자·중간 편집·하이픈 삭제를 처리합니다. 필드에서 벗어날 때 오류를 안내하고 다음/제출에서도 재검증합니다.
- 성명·매장명·전화번호·주소·업종·사업자 번호 체크섬을 검증합니다. 실제 사업자 자격 및 월계1동 행정동 소재 여부는 서버/운영자가 확인해야 합니다.
- 업종 선택창은 [Figma 436:2114](https://www.figma.com/design/ZaFHresnBXJ1h98Xl1AUDj?node-id=436-2114)를 따르며 공통 Choice/Button/PickerDialog를 재사용합니다. 음식점·카페·편의점·기타 중 선택 완료 시 반영하고 닫기/Escape는 기존 값을 유지합니다. API 제출 시 선택 업종을 명세의 Industry 코드로 변환합니다.
- 주소 선택 시 우편번호·기본 주소를 채우고 이전 상세주소를 초기화합니다. 상세주소는 선택 항목입니다.
- [Kakao 우편번호 공식 가이드](https://postcode.map.kakao.com/guide)의 embed 방식을 사용합니다. 검색 버튼을 눌렀을 때만 외부 SDK를 로드합니다. 검색어는 해당 서비스로 전달됩니다. SDK 및 iframe 로드 시간 제한, 닫기, 재시도를 지원합니다.
- 임시 입력은 같은 탭의 sessionStorage에 30분 동안 저장합니다. 서버 제공 `draftScope`가 바뀌거나 만료·손상됐으면 복원하지 않습니다. 서버에서 확인한 이메일은 초안 범위로만 저장하고 인증 토큰은 저장하지 않습니다. 접수 시 삭제하고 가입 세션 만료 시에는 같은 이메일로 재인증한 뒤 복원할 수 있도록 보존합니다. 저장 기능을 사용할 수 없어도 메모리 내 진행은 유지합니다.
- 수정 시 요청 키를 새로 만들고 동일 내용의 실패 재시도에서는 같은 키를 사용합니다. 제출 중 중복 클릭·단계 이동·수정을 차단합니다. 늦게 도착한 취소 요청의 성공 응답은 무시합니다.

## 서버 연동 경계

기본 OwnerService는 `GET /api/auth/registration`으로 확인한 이메일을 표시하고 `POST /api/auth/registrations/owners`로 점주 정보와 최초 매장 신청을 제출합니다. `credentials: include`, CSRF 및 멱등성 key와 10초 제한은 공통 API 클라이언트가 적용합니다. 서버 Session의 OWNER/OWNER_APPROVAL_PENDING과 PENDING 매장을 접수 결과로 변환합니다. 성공 후 제품 흐름은 `/home`에서 회원 세션을 다시 확인하고 승인 대기 화면을 표시합니다.

사업자 번호는 명세의 10자리 숫자 패턴으로 검사하고, 휴대전화는 010 11자리, 매장 전화는 0으로 시작하는 9~11자리, 상세주소는 최대 200자입니다. 매장 주소와 서비스 지역 및 중복 사업자 번호의 최종 판단은 서버가 수행합니다. 422 fieldErrors는 폼 필드로 변환하고 오류 code별 안내를 표시합니다. 가입 세션 만료 후에는 입력을 보존하지만 재인증 전 제출은 차단합니다. 실제 Google·가입·쿠키 전환의 E2E는 사용자 검증 대상입니다.

알림 및 추가 매장 등록은 아직 별도 기능이 없어 준비 안내를 표시합니다. 승인 전 운영 버튼은 원본 승인 안내 모달로 연결합니다.

## 검증

- `npm run test:ci --prefix front-end`: 22개 파일, 114개 테스트 통과. 단계 이동·수정·보존·중복 요청·서버 거절·만료·주소 콜백·검색 시간 제한을 포함합니다. 서버 응답은 테스트 대역으로 검증했습니다.
- `npm run lint --prefix front-end`, `npm run build --prefix front-end`, `git diff --check` 통과. production JS에 preview 경로/샘플 이메일/샘플 접수 식별자가 없음을 확인했습니다.
- 기존 Safari를 재사용하여 390×844 가입 흐름과 승인 대기, 업종 선택, 주소 검색 실패 안내, Escape 닫기를 확인했습니다. 320px 승인 안내의 줄바꿈과 1440px 중앙 정렬도 확인했습니다.
- 매장 화면: 진행 표시 x24/y72/342×32, 소개 x24/y124/342×67, 첫 필드 x24/y211/342×79. 원본과 일치합니다.
- 승인 대기: 소개 y68/67px, 카드 y159/173px, 추가 버튼 y356/23px, 안내 y403/64px, 공고 제목 y491/29px, 빈 상태 y544/102px, 하단 메뉴 76px. 1440px 화면에서 프레임 x525/390px 확인했습니다.
- 원본에서 받은 bell/home/book/brief SVG는 모두 로컬 24×24px이며 브라우저에서도 로딩 완료와 크기를 확인했습니다. AppBar와 선택 필드는 기존 원본 아이콘을 재사용합니다.
- 주소 검색 SDK는 로드됐지만 외부 HTTP iframe에서 `HTTP 재이동이 너무 많음` 오류가 발생했습니다. 10초 후 실패 안내 및 닫기/재시도 제공을 확인했으며 실제 검색 결과 선택은 미검증입니다. HTTPS 배포 환경에서 추가 확인이 필요합니다.
- 콘솔에 출처 URL이 없는 리소스 접근 권한 오류도 관찰됐습니다. 앱 런타임 오류와 framework overlay는 관찰되지 않았지만 해당 리소스 오류의 원인은 확인하지 못했습니다.
- 실제 모바일 기기, Google SSO, 백엔드 가입/접수, 운영자 승인 후 전환은 미검증입니다. stacked PR 대상 브랜치에는 현재 CI 트리거가 없어 로컬 검증을 수행합니다.

## 성명 정책

외국인도 가입 대상입니다. 성명에 한글 전용 또는 5~6자 제한을 적용하지 않으며 공백·하이픈·아포스트로피·비라틴 문자도 허용합니다. 현재 1~50자는 법적 제한이 아닌 서비스 입력 상한이며 서버 계약 확정 시 다시 확인합니다. 프론트엔드 입력 검증은 실명 확인을 대신하지 않습니다.
