# 로그인·가입 유형 선택

#28은 Figma의 [로그인](https://www.figma.com/design/ZaFHresnBXJ1h98Xl1AUDj?node-id=192-5290)과 [가입 유형 선택](https://www.figma.com/design/ZaFHresnBXJ1h98Xl1AUDj?node-id=192-5299)을 구현합니다. 공통 UI #35 위에 쌓은 PR이며 dev에 병합하지 않습니다.

## 확인 경로

- `/`, `/login`: 실제 세션 조회와 연결되는 로그인 화면입니다.
- `/signup`: 기존 세션은 홈으로 이동하고, 401 응답과 signup_csrf 힌트가 있으면 가입 유형을 표시합니다.
- `/signup/owner`, `/signup/worker`: #29·#30의 가입 화면 진입점입니다. 현재는 준비 안내만 표시하며 계정을 생성하거나 가입을 완료하지 않습니다.
- `/home`: 검증된 기존 세션의 홈 진입점입니다. 홈 구현 전까지 준비 안내만 표시합니다.
- `/status`: 기존 API·DB 상태 확인 화면입니다.
- `/__auth/signup`: 개발 모드 전용 시각 확인 경로입니다. 인증 정보를 만들지 않습니다. 버튼을 누르면 실제 가입 가드 경로로 이동합니다.
- `/__ui`: 기존 개발 전용 공통 UI 확인 경로입니다.

```bash
cd front-end

npm run build
```

## 현재 연동 상태

저장소 백엔드에는 health만 구현되어 있습니다. 2026-09-23 로컬 OpenAPI 초안의 AUTH-01·02·04를 확인해 프론트엔드 어댑터를 작성했으며 실제 카카오 인증 성공을 검증한 상태는 아닙니다. 인증 API가 없거나 응답이 잘못되면 오류로 처리합니다. 테스트에서만 fetch를 모사하며 제품 코드에는 데모 세션·역할 전환·localStorage 계정이 없습니다.

| 계약 | 프론트엔드 처리 |
| --- | --- |
| `GET /api/auth/kakao/start?returnPath=%2Fhome` → 302 | 페이지 전체를 이동합니다. 클라이언트가 provider 토큰이나 state를 생성하지 않습니다. |
| `GET /api/auth/kakao/callback` → 303 | 백엔드가 code/state를 검증합니다. 기존 계정은 session 쿠키 설정 후 `/home`, 신규 계정은 등록 티켓과 signup_csrf 쿠키 설정 후 `/signup`으로 이동합니다. |
| `GET /api/me` → 200 `{data: Me}` | id(UUID), displayName, accountType(OWNER/WORKER), sessionExpiresAt, csrfToken을 검증합니다. |
| `/api/me` → 401 | 비로그인으로 처리합니다. 403·404·429·5xx·잘못된 JSON은 비로그인 성공 응답으로 간주하지 않습니다. |
| 세션 쿠키 | 같은 출처에 전송합니다. 토큰을 URL이나 로컬 저장소에 기록하지 않습니다. 요청은 8초 제한과 취소를 지원합니다. |

`signup_csrf`의 존재는 가입 화면을 표시하는 UX 힌트일 뿐 인증 증거가 아닙니다. 서버는 가입 제출 시 HttpOnly `registration_ticket`의 유효성·일회성·CSRF와 Origin을 반드시 검사해야 합니다. 만료 여부를 조회하는 가입 상태 API는 현재 초안에 없습니다. 실제 만료된 티켓 처리는 #29·#30의 제출 응답과 연결해야 합니다.

초안은 거절 시 로그인 오류 경로로 이동한다고만 명시합니다. 백엔드와 맞출 앱 오류 경로로 `/login?error=access_denied` 또는 `/login?error=failed`를 제안합니다. 첫 번째는 취소 안내, 그 외 오류는 일반 실패 안내를 표시하고 URL의 쿼리를 지웁니다. error_description·임의 redirect·role 값은 화면에 반영하지 않습니다. 실제 callback 허용 URL과 카카오 앱 설정은 서버 구현 시 확정해야 합니다.

## 화면과 접근성

MobileLayout·AppBar·Button·Modal을 재사용합니다. 최대 너비는 390px이며 넓은 화면에도 동일한 모바일 배치를 중앙 정렬합니다. 작은 화면에서는 본문이 스크롤합니다. Figma export SVG 4개를 로컬에서 사용하고 root 크기를 유지합니다. 52px 인증 버튼과 로그인 전용 여백은 해당 화면 CSS에서 적용합니다.

Figma 텍스트 박스의 정수 높이에 맞춰 13px/15px/17px/19px 텍스트의 줄 높이를 20px/23px/26px/29px로 적용합니다. 이 보정으로 소수점 줄 높이의 누적 차이를 제거합니다. 기본 공통 UI의 수치는 변경하지 않습니다.

취소·실패 안내는 공통 Figma Modal을 조합합니다. 해당 문구와 네트워크 상태는 로그인 원본에 없는 동작 상태입니다. 재시도 중 중복 요청을 막고 닫기·Escape로 취소하면 늦은 응답도 무시합니다. 브라우저 뒤로가기와 bfcache 복귀 시 세션을 다시 확인합니다.

## 검증 기록

2026-09-24: lint·build·테스트 64개·diff 검사가 통과했습니다. 테스트는 서버 실패, 만료·잘못된 세션, 취소, 재시도, 중복 클릭, 늦은 응답, 기존 계정 분기, 역할별 진입점 및 브라우저 복귀를 포함합니다.

기존 Safari를 재사용했습니다. 인앱 브라우저는 제공된 URL의 탭을 도구에서 찾지 못해 조작하지 않았습니다. 390×844, 320×568, 1440×900에서 화면을 확인했습니다. 320px 가입 화면의 스크롤과 로그인 오류·재시도·Escape 포커스 복귀를 확인했습니다. 1440px 화면에서 프레임 너비 390px, x=525를 측정했습니다.

Pretendard GOV 로딩 및 로그인 SVG의 자연 크기를 확인했습니다. Safari 콘솔의 `/api/me` 502는 실행 중인 인증 백엔드가 없는 환경의 실패 응답입니다. 별도로 URL이 표시되지 않은 리소스 접근 권한 오류 3건이 관찰되어 출처를 확정하지 못했습니다. 화면의 폰트·아이콘은 로딩되어 있으며 프레임워크 오류 화면은 없었습니다. 콘솔 오류가 전혀 없다고 주장하지 않습니다.

실제 카카오 로그인, 서버 쿠키 발급, 실기기 키보드와 자동 이미지 픽셀 diff는 검증하지 않았습니다. 성공·신규 계정 분기는 명세 응답을 모사한 테스트 결과입니다. 현 CI는 PR base가 main 또는 front-end/dev인 경우에만 실행되므로 stacked PR에서는 자동 실행되지 않습니다. 배포를 유발하는 dev 병합은 수행하지 않습니다.
