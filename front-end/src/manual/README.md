# 점주 매뉴얼 작성 MVP

음성 답변·음성 정정 범위를 유지하며 Figma의 질문, 이해 확인, 사진, 최종 검토와 미리보기를 구성합니다. 전사 원문 편집·선택형 답변·사진 이름/설명 입력은 제공하지 않습니다.

## API와 적용 순서

`types.ts`와 `contract.generated.ts`는 OpenAPI 0.11.0, **PR #159의 52f75249c359384a006dc4f1e2cc716ef62b67fb**에서 선택한 점주 매뉴얼 26개 operation의 스냅샷입니다. 선행 PR이 아직 병합되지 않은 상태에서 연결했으므로 병합 전 계약 변경 여부를 확인해야 합니다.

1. #159 계약 확정 후 이 프론트의 응답 검증기·렌더러를 먼저 적용합니다.
2. #119/#120 서버가 guidance, guidanceCards, lastAnsweredQuestion을 저장·송출하도록 구현합니다.
3. #131에서 인증·매장 선택·운영 진입을 연결하고 실제 서버로 검증합니다.

새 필드는 선택 필드여서 기존 응답도 허용합니다. 누락된 카드 내용을 질문 문자열로 추측하지 않습니다. 구 서버에서 처리 중 스냅샷이 없으면 현재 탭은 마지막 질문을 유지하며, 새로고침에서는 일반 준비 상태를 표시합니다. 서버가 전달하는 순서·ID·revision을 사용합니다. 카드당 CURRENT 최대 하나를 런타임 검증합니다.

## 상태와 화면 책임

- `useManualInterview`: 세션·검토 목록 조회, revision 갱신, 질문과 복원 스냅샷, 음성 답변.
- `useManualIntentReview`: 주제별 확인·정정. 세션 revision과 검토 revision을 혼용하지 않습니다.
- `useManualDraftReview`: 초안·정정 작업 조회, 게시, 부족 항목 확인, 사진 변경 후 캐시 무효화.
- `ManualQuestionScreen` / `ManualGuidanceCard`: 서버의 LIST / PROGRESS_CHECKLIST / PHOTO_SUGGESTIONS 표시. 진행 체크는 읽기 전용입니다.
- `ManualUnderstandingScreen`: 주제별 요약과 사진 묶음. 공통 업무에 관계없는 근무조를 표시하지 않습니다.
- `ManualPhotoEditor`: 선택·빈 상태·삭제 확인·재시도. 검토/초안 어댑터가 각각 API를 담당합니다.
- `ManualDraftSummary` / `ManualDraftDetail`: 분류별 요약과 상세·음성 수정·사진 관리 진입.
- `ManualIssuesScreen`: 게시 전 부족 항목 확인. 미리보기는 확인을 대신하지 않습니다.

완료된 intent 중 미확인 검토를 서버 배열 순서대로 보여준 뒤 다음 질문을 노출합니다. 요약이 아직 도착하지 않아도 다음 질문을 먼저 노출하지 않습니다. 확인 상태는 서버 confirmedAt을 사용하므로 새로고침으로 건너뛰지 않습니다. **이는 프론트 전환 정책입니다. 기존 서버의 completion 선행 조건 자체는 변경하지 않습니다.** 기록·이전 주제 목록·나중에 확인하기·depth 숫자 UI는 제거했습니다.

정정 중 추가 정정·게시를 차단합니다. 실패 시 이전 내용을 보존하고 명시적으로 재확인한 경우에만 게시할 수 있습니다. 오류는 Modal로 표시하고 정상 녹음·답변 처리 안내는 하단에 유지합니다. 부족 항목이 남아 있을 때 `확인하고 게시`는 확인 화면을 열고 publication 요청은 보내지 않습니다. 확인 저장 후 전체 검토에서 게시를 다시 선택합니다.

## 사진과 미리보기

사진은 근무 구조 또는 sectionId에 연결합니다. 사진 추천 항목 ID는 연결 대상 ID가 아닙니다. 첨부 직전 READY 검토를 다시 읽고 대상/검토 ID를 확인합니다. 대상이 null이면 추천만 표시합니다.

사진 요청 화면은 추천 카드의 첨부 버튼에서 진입하는 **선택적 첨부 화면**입니다. `사진 없이 계속하기`는 원래 질문으로 복귀하며 답변·intent 완료를 자동 제출하지 않습니다. Figma처럼 사진 선택/생략만으로 인터뷰의 다음 주제로 전환하려면 별도의 서버 phase/완료 명령 계약이 필요합니다. #159는 이 계약을 포함하지 않으므로 이번 프론트에서 임의로 만들지 않았습니다.

신규 사진은 `사진 N`, caption=null입니다. JPG·PNG·WebP, 10 MiB 이하, 대상별 20장 상한을 유지합니다. 삭제는 확인 후 연결 해제이며 공유 미디어를 삭제하지 않습니다. 취소 시 요청하지 않고 실패 시 사진을 유지합니다. 업로드·연결 요청 유실은 같은 키·본문으로 재시도합니다. 초안 편집은 전체 content PUT에 versionId/revision을 고정하며 다른 업무를 보존합니다.

카메라는 capture=environment, 앨범은 image/*, 파일은 허용 MIME 입력을 사용합니다. 실제 카메라/앨범 UI 제공 여부는 브라우저·기기에 달려 있으며 데스크톱에서는 파일 선택창으로 대체될 수 있습니다. 모바일 실기기 카메라/앨범은 미검증입니다. HEIC 등 미지원 형식은 안내 후 재선택합니다.

읽기 화면 사진은 1장 전체 폭, 2장 2열, 3장 이상 3열로 줄바꿈합니다. 편집 화면은 세로 카드입니다. 기존 사진 순서 이동 버튼은 제거했습니다.

미리보기는 서버 section 순서와 개수를 사용합니다. 첫 페이지는 돌아가기/다음, 중간은 이전/다음, 마지막은 이전/검토 완료입니다. 1개는 검토 완료만, 0개는 빈 안내와 돌아가기입니다. 완료는 검토 화면으로 돌아갈 뿐 게시·부족 항목 확인을 수행하지 않습니다.

## 검수

`/__manual`은 샘플 서비스 전용이며 운영 빌드에서 제외됩니다. 실제 API·인증·STT·AI·저장소·운영 진입 연결은 #131 범위입니다. 이 변경만으로 실제 서버 연동이나 배포가 완료되지 않습니다.

- `?resume=1`: LIST 질문
- `?case=checklist`: 대기/현재/완료/보완 필요
- `?case=processing`: 새로고침 후 질문 스냅샷 유지
- `?case=photo-request`: 추천 대상 → 요청 화면 → 사진 편집
- `?case=review`, `review-error`, `depth5`, `ready`: 주제 검토와 최종 진입
- `?case=draft`, `missing`, `correction-running`, `correction-error`, `correction-clarify`, `correction-noop`, `generation-error`: 초안·정정·확인

`npm run lint`, `npm run test:ci`, `npm run build`로 검사합니다. UI 시험은 in-app browser 우선이며 실제 마이크 권한·모바일 사진 접근과 서버 E2E를 샘플 검증 결과에 포함하지 않습니다.

## 실제 API 진입 연결 (#166)

`/home?view=manual&store=...`에서 점주에게는 디자인 정합화된 작성 화면, 근무자에게는 게시 목록·상세 기본 조회를 제공한다. `liveManualService`가 실제 세션과 요청별 CSRF를 연결한다. 위의 샘플 전용 검수와 실제 인증 진입을 구분하며, 상세 범위·검증 한계는 [workspace 안내](../workspace/README.md)를 따른다. AI 질문과 근무자 화면 전체 디자인 정합화는 여전히 후속 작업이다.
