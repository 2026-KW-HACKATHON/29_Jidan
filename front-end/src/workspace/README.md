# dev API 화면 연결

기준: dev OpenAPI **0.10.1**, backend `e5dfb48999468fab1d811ff60ae4a6e7bd1d644c`.
실제 주소는 같은 origin의 `/api`이며 dev/운영 간 쿠키나 절대 URL을 공유하지 않는다.

## 진입과 연결 범위

`/home?view=...&store=...&id=...`는 인증 경계에서 세션을 재검증한다. 뒤로가기·새로고침도 같은 서버 리소스를 조회한다. 점주 매장 권한은 홈 응답으로 버튼 진입을 검사하고 각 API에서 다시 검증한다.

| 화면 | 실제 요청 |
|---|---|
| 점주/근무자 홈 | 역할별 홈 집계, 한국 시간 월별 근무 일정 |
| 프로필 | 조회, 기본 정보 PATCH, 경력/가능 시간의 구역별 PUT |
| 공고 | 탐색/상세, 등록, 점주 목록/지원자, 지원/철회, 근무 요청, 모집 마감 |
| 매장 | 매장 선택/추가, 운영 집계, 근무자 목록/상세/접근 종료 |
| 초대 | 목록/생성/취소/재발송, 받은 초대 확인/수락/거절 |
| 메일 초대 | `/invitations/accept#token=...` 문맥 보관 후 로그인·가입 복귀, preview/accept/decline |
| 알림 | Figma 목록·읽음 필터·상대 시간, 읽음 처리, 타입별 내부 화면 이동 |
| 근무 요청 | 받은 요청 상세와 수락/거절, 점주 대기·미응답·확정, 요청/확정 철회, 서버 revision 사용 |
| 신청 내역 | 근무자 홈의 신청 중 공고 → 서버 탭별 목록·집계 → 실제 지원 ID 상세 |
| 확정 온보딩 | 점주 지원자 상태 → 온보딩 조회 → 게시 버전을 고정한 매뉴얼 목록·절차·사진 |
| 점주 매뉴얼 | 기존 음성 인터뷰/정정/사진/초안 검토/게시 서비스에 실제 CSRF·세션 연결 |
| 근무자 매뉴얼 | 접근 가능 매장, 게시 목록/업무 상세/사진 조회 |

목록은 서버 페이지를 순차 조회하며 빈 목록·0건은 그대로 표시한다. 100페이지를 넘기면 무한 요청 대신 오류로 중단한다. 현재 UI의 검색 필터는 가져온 공고에 적용한다. 대규모 목록의 서버 검색/점진 로딩은 별도 최적화다.

## 실패·동시성

- GET 및 변경 응답을 배포 계약으로 검사한다. 잘못된 응답은 가짜 성공이나 샘플 데이터로 바꾸지 않는다.
- 401은 로그인 화면으로 이동, 403/404 등은 현재 화면에서 실패·재시도를 제공한다.
- 변경 직전 CSRF를 조회하고 멱등성 키를 전송한다. 응답 유실 재시도에는 같은 의도의 키를 유지한다.
- 지원 철회/공고 마감/근무 요청·응답은 화면에서 읽은 revision을 전송한다. 충돌 시 실패로 남겨 뒤로가기·새로고침으로 최신 상태를 다시 읽도록 한다.
- 화면 이탈 시 요청 취소, 중복 제출 방지, 요청 대상 변경 시 이전 응답 노출 방지를 적용한다.
- 메일 토큰은 fragment에서 즉시 지우고 sessionStorage에서 최대 1시간 보관한다. 완료·취소 시 삭제하며 URL query/로그/분석에 넣지 않는다. 저장소를 차단한 브라우저는 로그인 후 메일 링크를 다시 열어야 한다.

## 남은 범위와 검증 한계

- `api/types.generated.ts`의 모든 operation이 화면에 노출되는 것은 아니다. 관리자 API, 체크리스트 완료 저장, 관심 매장 편집은 이번 기존 화면 연결의 완료 범위가 아니다. 근무자 AI 질문은 [Q&A 구현 및 검증 범위](../qa/README.md)에서 별도로 설명한다.
- 근무자 게시 목록/상세는 기존 공통 UI를 이용한 기본 조회다. #131의 매뉴얼 열람 화면 전체 디자인 정합화를 뜻하지 않는다. AI 질문은 매뉴얼 하단 진입 버튼에서 별도 화면으로 연결한다.
- #161의 매뉴얼 디자인 변경을 통합했다. #159의 새 optional 안내 필드는 배포된 0.10.1에서 아직 송출되지 않는다. 기존 응답 허용을 검증했으며, 동적 안내 카드 제공과 사진 선택/생략만으로 인터뷰를 진행하는 명령은 서버 후속 작업이다.
- 캘린더 API는 읽기 전용이므로 실제 화면의 임의 일정 등록 버튼은 숨긴다.
- 자동 UI 테스트와 OpenAPI 예시 호환성 검사는 인증된 dev 사용자의 실제 저장·메일 발송·마이크·STT/AI 검증을 대신하지 않는다.

## 사용자 페이지 연결 검증 (#168)

사용자 지정 브랜치 `front-end/feat/user-pages`를 유지한다. `front-end/dev` 기준 이식이며 원본 브랜치의 오래된 인증·앱 설정은 가져오지 않는다. Figma 파일 `ZaFHresnBXJ1h98Xl1AUDj`의 알림(506:3842, 506:3834), 신청 내역(506:3929, 506:3969, 506:3996), 지원자(698:2714, 698:2765, 698:2821, 698:2981)와 미리보기의 13개 상태를 대조했다.

운영 진입점은 `/home?view=notifications`, `/home?view=applications`, 점주 `/home?view=job&store=<storeId>&id=<jobId>`다. 다른 지원자는 `view=applicants`, 확정 온보딩은 `view=onboarding`에서 같은 공고를 읽는다. 미리보기의 샘플 데이터는 운영 빌드에 포함하지 않는다.

검증에는 backend `d35c26d`의 별도 `jidan-user-pages-check` Compose 프로젝트와 `jidan_e2e_test` MySQL을 사용했다. 기존 개발·운영 DB는 사용하지 않았다. 실제 UI → HTTP → API 재조회 및 별도 DB 연결로 알림 읽음, 요청 철회, 확정 철회, 공고 재모집, 임시 접근 종료, 미응답 요청 정리와 공고 마감을 확인했다. 미응답은 격리 DB의 시간 fixture로 준비했고 이후 읽기·마감은 실제 구현으로 처리했다. 브라우저의 API 응답이나 handler를 mock으로 대체하지 않았다.

빈 목록·조회 실패/재시도·빠른 탭 전환·중복 클릭·응답 유실·멱등 키 유지·revision 충돌·근무 시작 후 철회 차단·게시 버전 교체·미게시 상태를 자동 UI 시험으로 검증한다. 실제 HTTP에서는 잘못된 역할의 403, 승인 대기 매장의 기능 차단, 미인증 로그인 경계도 확인했다. 320px 화면과 기존 미리보기의 20개 화면 크기 조합에서 가로 넘침을 검사했다.

로컬 로그인 세션은 데모 계정 fixture다. 외부 Google/Kakao 인증, 실제 사용자의 개발 서버 저장, 메일·마이크·STT/AI는 이번 검증에 포함하지 않는다. 이 브랜치는 frontend 개발 통합용이며 `main` 릴리즈를 의미하지 않는다.

```sh
cd front-end
CI=true npm run test:ci -- --maxWorkers=2
npm run lint
npm run build
node scripts/verify-preview-build.mjs
```

운영 빌드에는 기존 500kB 초과 번들 경고가 남아 있다. 알림·신청 목록은 최대 100페이지를 읽으며 점진 로딩은 별도 후속 최적화다. 온보딩은 서버의 현재 게시 버전에 대한 읽기 전용이며 게시 전 초안은 표시하지 않는다.
